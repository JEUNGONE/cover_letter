## 자기소개 & AI를 공부하게 된 계기

Out [2]

안녕하세요. 데이터 속 문제를 찾아내고 모델로 풀어내는 과정에 재미를 느끼는 AI 전공 3학년 학생입니다. 처음 이 분야에 관심을 갖게 된 것은 수업에서 실제 판매 데이터를 다뤄보면서였습니다. 매출이 떨어진 이유를 숫자로 되짚어보다가, 제가 세운 가설이 실제로 맞아떨어지는 걸 보고 소름이 돋았던 기억이 있습니다.

그 이후로 머신러닝과 생성형 AI를 독학하기 시작했고, 지금은 데이터를 정리하고 모델을 학습시키는 것을 넘어 LangChain과 OpenAI API를 활용한 RAG 구조까지 직접 구현해보며 범위를 넓혀가고 있습니다. 이론으로만 아는 것과 직접 손으로 만들어본 것은 다르다는 걸 매 프로젝트마다 느낍니다.

Python Pandas Scikit-learn

서비스 이용 로그 데이터를 바탕으로 이탈 가능성이 높은 고객을 미리 예측하는 것이 목표였습니다.

어떻게 진행했는지 자세히 보기
목표
이탈 가능성이 높은 고객을 사전에 예측해 대응할 수 있도록 하는 것.
내 역할
데이터 전처리와 모델 학습, 성능 검증을 담당했습니다.
어려웠던 점
초기 모델 정확도가 기대만큼 나오지 않았고, 원인을 찾는 데 시간이 걸렸습니다.
해결 방법
원인을 살펴보니 결측치 처리 방식이 데이터 특성과 맞지 않았습니다. 여러 처리 방식을 비교 검증하며 로직을 다시 설계했습니다.
성과
예측 정확도를 [수치] 까지 끌어올렸습니다.
배운 점
모델 성능은 알고리즘 선택보다 데이터를 이해하는 힘에서 나온다는 것을 배웠습니다.

[진행 기간 입력]
LangChain OpenAI API FAISS Streamlit

3명이 함께한 팀 프로젝트로, 문서를 검색해 질문에 답하는 챗봇을 만드는 것이 목표였습니다.

어떻게 진행했는지 자세히 보기
목표
사내 문서를 검색해 정확한 답변을 제공하는 RAG 기반 챗봇 구현.
내 역할
문서 임베딩과 검색(retrieval) 파트를 맡았습니다.
어려웠던 점
검색 결과와 실제 필요한 답변이 어긋나는 문제가 반복됐습니다.
해결 방법
팀원들과 매주 진행 상황을 공유하며 청크 분할 기준을 바꿔보고 프롬프트를 여러 번 수정했습니다. 의견이 갈릴 때는 각자 근거를 데이터로 보여주며 논의했습니다.
성과
답변 정확도를 눈에 띄게 개선했습니다. ([수치] 입력 가능)
배운 점
팀에서는 감정보다 근거로 논의할 때 더 빠르게 좋은 방향을 찾을 수 있다는 것을 배웠습니다.
